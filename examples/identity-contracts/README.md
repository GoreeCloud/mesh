# Identity-verified synthetic Mesh status read — isolated acceptance

**Status:** Development-only source-integrity and authorization contract. **Not** a deployed GoreeCloud Identity connector, live Keycloak integration, real Wardveil user access, remote JWT verification service, or production authorization.

The [isolated Identity contract workflow](../../.github/workflows/identity-mesh-contract.yml) checks out the authorized GoreeCloud Identity source at immutable commit `703cb1b55f29e849d90f3281bb582cf33ee78804`. Before running, it verifies the source identity and Git blobs of the actual `ResourceAuthorizer`, token verifier, policy implementation and the `PyJWT[crypto]==2.15.1` dependency declaration. It runs the original Identity Python verifier, not a reimplemented JWT decoder. Python cryptography is Identity's existing third-party development dependency; a complete supply-chain audit and license approval are **not** claimed.

A disposable 2048-bit RSA signing key and corresponding test public JWK are generated in memory solely for this hosted CI experiment. Test-only signed access JWTs exercise valid issuer, audience, authorized client, signed tenant, required scope, explicit role, explicit deny override, expiry, token class, signature algorithm and unknown signer. No actual Keycloak user, issuer network, production signing material or real customer tenant is used.

The [synthetic reader gate](identity-verified-reader.mjs) accepts exactly one opaque bearer; the caller cannot provide the tenant, resource, action, actor, authorization result, signing key, URL or policy. It requires a separately **trusted injected verifier** to return the literal Boolean `true` on every request for the fixed `synthetic-family / wardveil.status / read` scope, and then invokes the existing Mesh synthetic harness with a fixed diagnostic actor. Even an Identity allow cannot bypass the independent Mesh or owner permit. Any missing, malformed, wrong-tenant, expired or unauthorized token fails closed as `denied` before an owner read. A bounded verifier timeout and in-flight admission limit reject stalled validation, holding capacity until an actual verifier settles; they are not hard process cancellation or production worker supervision.

The fixture verifier's public JWK is supplied by the **trusted test harness**. **Never** accept caller-supplied JWKS or verifier callbacks in a real product. A production consumer must pin GoreeCloud Identity's issuer and trust roots, use supported JWKS cache and secure transport, enforce tenant/resource ownership at the source, implement short-lived token and session revocation, protect credentials and apply GoreeShield privacy/consent where applicable. The test does not bind an actual Identity-verified user to a Wardveil Go status request; Wardveil still uses a separate static status-only development bearer.

The [Node tests](identity-verified-reader.test.mjs) run only inside the isolated CI job, not default `npm test` (they require the pinned authorized Python source checkout). Results are not automatically a Stable release or deployment authorization.
